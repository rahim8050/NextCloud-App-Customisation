## What we discovered (Raster)
- The current “raster” call is effectively returning **an error JSON** (`status: 1`, `"Raster not found"`) where the UI/clients expect a **real PNG**.
- This points to the raster layer not being produced or not being located by the API (i.e., no raster generated/stored for the requested params, or lookup keys don’t match).
- Sentinel Hub is not usable for us right now (account closed), so the raster needs to come from the **new engine path** (e.g., STAC-backed fetching/processing) rather than the old provider assumptions.

## Next

  - Stable lookup keys (farm + date range + bbox/resolution + product type) so we can consistently find cached rasters.
- Wire Nextcloud to the finalized raster endpoint and render the result reliably (binary fetch; no accidental JSON-to-img).
- Add “truthful” error behavior:
  - 404/empty state when raster is genuinely missing,
  - explicit error codes/messages in JSON only when requested, not when the route is supposed to be PNG.
